# 各模型写法与忌讳（model-guides）

先选模型，再写提示词。每个模型脾气不一样：有的吃分段结构，有的吃自然语言，有的认参数。写之前先看这一篇，写完对照“忌讳”过一遍。

总原则：下面只写有把握的通用写法。某个模型的参数名、版本号、额度、单 clip 时长限制，不确定的地方都标了“以官方最新文档为准”——不要猜，生成前去官方页面核对一眼。

---

## Seedance（参考图生视频）

**适合**：手里有参考图，想让图里的人 / 场景动起来；想锁定开头和结尾画面。

**写法**：

- 提示词分七段写，顺序是：目标 → 参考图分工 → 人物与站位 → 事件分段 → 镜头与光线 → 声音 → 收尾与一致性。段落之间意思分开，不要揉成一段。
- 参考图一张管一个角色：一行写清这张图负责什么（脸、发型、衣服），只写图中直接看得见的东西；身份、年龄、关系、剧情只从用户文字里取。
- 想锁定开头画面，单独写一句 `@Image N is the first frame.`，再另起一句描述这帧的构图；想锁定结尾画面，同样写一句 `@Image N is the last frame.`。开头那帧决定输出比例，首尾两帧比例必须一致。
- 想让两段视频无缝接上：把上一段的最后一帧抽出来，当下一段的开头帧用。
- 事件分段写：每段只讲一件主要的事，段尾落到一个能看见的画面上。先写触发事件，再写随之而来的反应。
- 声音分四种写，标记分开：`()` 音乐、`<>` 音效、`{}` 对白、``字幕。对白只能用用户原话。
- 镜头和光要写具体：不要写“运镜很棒”，要写“低角度跟拍，镜头慢慢推向门口”；不要写“光线很美”，要写“头顶一盏钠灯，光从上往下打”。

**忌讳**：

- 否定词：`no`、`without` 这类词会把不想要的东西带进画面，改写成正面状态或删句。
- 一段里塞多个变化：模型会丢动作，拆成多段写。
- 镜头轴线乱跳：全程保持在动作轴的同一侧，不然人物方向会左右翻转。
- 对白编造：用户没给台词就不要编。
- 景别、焦段、距离互相打架：远景就别配特写的要求。
- 首尾帧比例不一致：锁定前先确认两张图比例相同。

**语言**：英文优先。锁定句式、音频标记都是英文语法，提示词正文用英文最稳；中文提示词在部分版本里能用，但首尾帧锁定句和音频标记永远用英文原句。

## Kling（叙事短片）

**适合**：有故事的短片，几十秒、几个镜头，要电影感、要人物稳定。

**写法**：

- 叙事默认用多镜头：一个 clip 由几个 3–5 秒的小镜头切出来，比一个长镜头更像电影；只有特别短的节拍才用单镜头。
- 每段提示词分五块写：镜头与动作、环境、光影、台词、环境音。镜头动作里写清景别、运镜、人物动作、视线方向和细微表情；环境里写背景里会动的东西（人群、烟、风、雨、车流）以及它们离镜头多远；光影里写时间、光质和这场戏的情绪张力；台词只写原话；环境音写 3–4 层真实世界里的声音，只写环境本身的声音，不加音乐、不加夸张的转场音效。
- 角色一致性靠锚点：给每个角色写一段一字不改的外貌描述，生成一张锚点图，在 Kling 里注册成带名字的标签（比如 `@阿远`），之后每段提示词只用标签，不再重复描述长相；每段只写动作、服装状态和光线。多角色同框时用发型、服装、剪影区分开。
- 原生对白容易出金属音：每句台词前面加一段固定的声音描述，讲清三件事——嗓音什么样、录音质感怎么样、明确不要金属感。比如：“嗓音温和、语速放慢，像对着专业话筒近距离说话，声音干净，没有电流杂音。”同一部片子每句台词都用同一段描述。
- 台词按自然断句拆：一个人一句话太长，就按句子断成几段，一段一个镜头接着说，不要改词、不要调顺序。
- 环境、光影、环境音在同一个场景的几个镜头里保持连续，剪出来才像一场戏。

**忌讳**：

- 剧情、人物、结局不要“优化”：改编只做压缩和可视化，不改故事本身。
- 不要配乐、不要夸张的转场音效：情绪靠表演、画面和留白，安静本身就是表达。
- 同一个 clip 里不要既用原生对白又叠旁白，二选一。
- 声音描述不要一次叠多个负面音色词（又哑又沙又低），只留一个主音色。
- 角色锚点注册后不要再反复描述长相，越描越容易跑偏。

**语言**：英文优先，中文也行。叙事短片的英文提示词更稳；中文提示词在中文模型版本里效果好，台词本身按用户原话的语言写，不翻译。

## Midjourney（图片）

**适合**：单张高质量图片，风格化强，产品图、插画、概念图、头像。

**写法**：

- 自然语言描述为主，按图片九维写（主体、风格、材质、光线、构图、镜头、色彩、氛围、画质词），再加参数收尾。
- 常用参数（以官方最新文档为准）：`--ar` 定比例（如 `--ar 16:9`）；`--chaos` 调随机性，数值越高画面越意外；`--stylize` 调风格化强度；`--style raw` 让画面更贴近文字、少点艺术加工；`--no` 写不要的东西（如 `--no text, watermark`）。
- 版本号以官方最新文档为准，不要凭记忆写旧版本号。
- 风格词只锁一种；想换风格就换整套词，不要新旧混写。

**忌讳**：

- 提示词太长：超过有效长度的部分会被忽略，重要的词往前放。
- 风格词打架：开头写实、结尾卡通，模型只能折中出四不像。
- `--no` 里放剧情否定：只放画面通病类词（文字、水印、模糊、多余肢体）。
- 画质词堆叠：留一两个就够。

**语言**：英文优先。参数（`--ar`、`--no`、`--chaos`）全是英文，提示词正文用英文；中文提示词在部分版本里能用，但风格词和参数建议用英文。

## Nano Banana / Gemini 图像（图片编辑与生成）

**适合**：改图、修图、多图融合、换背景、换服装、保持人物一致出一组图。

**写法**：

- 用自然语言说人话：说清改什么、保留什么、改成什么样。模型按指令编辑，不用背参数。
- 多图参考时，每张图说清它负责什么（这张给脸、那张给衣服、这张给背景），不要只丢图不说话。
- 角色一致性靠参考图：一组图用同一张人物参考图打底，每张只改动作、场景和服装状态。
- 一次只改一两处：改动点写得越少越准。

**忌讳**：

- 一次改太多处：改脸又换背景又换衣服，模型顾不过来，拆成几步做。
- 描述和图矛盾：图里是短发，文字写长发，模型会随机应变，结果不可控。
- 把“不要”写进编辑指令：改成说“保留原样”或“去掉后补成背景”。

**语言**：中英文都行。自然语言编辑对中文理解好，中文指令直接写；英文指令同样稳。按用户说的语言出。

## Veo（视频）

**适合**：电影感短视频，运镜和光影要求高，有原生音频需求的片段。

**写法**：

- 用自然语言写电影感描述：主体、动作、镜头运动、光线、氛围按视频七维写全。
- 原生音频支持情况以官方最新文档为准；有对白时写清是谁在说、什么语气、原话是什么。
- 事件排得疏一点：单 clip 时长有限（以官方最新文档为准），一个 clip 只讲一两件主要的事。

**忌讳**：

- 事件排太满：演不完的部分模型会直接跳过或胡编。
- 镜头语言自相矛盾：又说固定机位又说环绕运镜。
- 忽略比例：首帧和生成比例不一致会裁切画面。

**语言**：英文优先。电影感描述和运镜词用英文更准；中文提示词在部分版本里能用，复杂运镜建议用英文版。

## Sora（视频）

**适合**：有故事板感的短片，多镜头叙事，风格化画面。

**写法**：

- 按分镜写：每个镜头一句话，说清景别、主体、动作、转场。
- 人物和风格在全片开头定死，后面每个镜头只写变化的部分。
- 具体功能（故事板、角色复用、混剪等）以官方最新文档为准。

**忌讳**：

- 同上：事件太满、镜头矛盾、风格漂移。
- 提示词里写实现不了的特效名词：写画面效果，不写软件功能名。

**语言**：英文优先。分镜描述用英文更稳；中文提示词能用，简单场景效果接近。

## GPT 图像（ChatGPT 出图）

**适合**：对话式改图、按文字指令修图、带文字的图（海报、表情包、示意图）。

**写法**：

- 用自然语言说人话：说清改什么、保留什么、改成什么样；一次只提一两处改动。
- 画面内有文字时，直接写出文字内容和语言（中文海报就写中文，一个字不改）。
- 可以多轮追改：上一张图的基础上说“把背景换成……”，不用重写全部。

**忌讳**：

- 一次改太多处：拆成几步做。
- 描述和图矛盾：图里是短发，文字写长发，结果不可控。

**语言**：中英文都行。中文提示词理解得好，中文海报、中文招牌直接用中文写；英文提示词同样稳。两种语言效果接近，按用户说的语言出。

## Flux（图片）

**适合**：细节多的图片、严格按文字执行的画面、写实和风格化都行。

**写法**：

- 提示词按图片九维写全，细节写得越具体越好，模型跟得上。
- 画面内文字：把文字内容写进提示词，写清是什么语言。

**忌讳**：

- 提示词太短太空：只写“一个女孩”，画面会很平；按九维补细节。
- 画质词堆叠：留一两个就够。

**语言**：英文优先。英文提示词执行最稳；中文提示词多数情况下也能用，但细节多的画面建议用英文版。

---

## Stable Diffusion（图片）

**适合**：可控性要求高的图片、风格实验、有负向提示词栏的工作流。

**写法**：

- 提示词用逗号分隔的词组写（标签式），按重要性从前到后排。
- 负向提示词栏单独写画面通病类词（多余手指、模糊、水印、文字乱码），不要放剧情否定。
- 风格词、画质词和主体词分开写，不要揉成一句话。

**忌讳**：

- 提示词写成大段散文：模型按词组理解，长句容易丢信息。
- 负向栏放剧情否定：`no running` 这类会反向执行。

**语言**：英文优先。标签式提示词基本是英文词组；中文提示词在部分版本里能用，但不如英文稳。参数名、版本号以官方最新文档为准。

## Runway（视频）

**适合**：电影感短视频、运镜控制、图生视频。

**写法**：

- 按视频七维写：主体运动、镜头运动、时间节奏、转场、首尾帧、音频、一致性。
- 有参考图时先定参考图角色，再写运动；运镜词写具体（推近、跟拍、环绕）。
- 单 clip 只讲一两件主要的事，事件排疏一点。

**忌讳**：

- 事件排太满：演不完的部分会被跳过或胡编。
- 镜头语言自相矛盾。

**语言**：英文优先。运镜和镜头语言用英文写更准；中文提示词在部分版本里能用，复杂运镜建议用英文版。

## Luma Dream Machine（视频）

**适合**：图生视频、运镜流畅的短片段、氛围感画面。

**写法**：

- 提示词写清主体、动作、运镜、光线四样，语言简洁，不要堆形容词。
- 有首帧图时，以首帧为准写运动和镜头，不要另起一套描述。

**忌讳**：

- 提示词太长：重点会被稀释，短而准更好。
- 一次塞多个动作：拆成多段。

**语言**：英文优先；中文提示词能用，简单场景效果接近，复杂运镜建议用英文版。

## 即梦（图片 + 视频）

**适合**：中文提示词出图、出视频；中文海报、中文招牌、中文短视频。

**写法**：

- 中文提示词直接写，结构按九维 / 七维，中文的细节描述模型跟得上。
- 画面内有中文文字时，直接写出文字内容，一个字不改。
- 视频按事件分段写，每段一件主要的事。

**忌讳**：

- 中文里夹英文参数：参数放生成设置里，不写进提示词正文。
- 一次塞太多元素：拆镜头、拆阶段。

**语言**：中文优先。这是中文模型，中文提示词效果最好；英文提示词也能用，但没必要绕一圈。

## 通用忌讳（所有模型都适用）

| 坑 | 错法 | 改法 |
|---|---|---|
| 否定词 | `no crowd` | 写正面状态：街道空无一人 |
| 模糊词 | beautiful, amazing, stunning | 换成可见的具体描述 |
| 画质词堆叠 | 8k, HDR, masterpiece 全上 | 留一两个 |
| 风格漂移 | 前半写实后半卡通 | 全篇只锁一种风格词 |
| 元素太多 | 一个画面 5 个主体 | 拆镜头、拆阶段 |
| 镜头矛盾 | 又固定又环绕 | 只留一种运镜 |
| 对白编造 | 用户没给台词就编一句 | 只写嘴部动作、停顿、姿势 |
| 画面文字混语言 | 招牌中英混排 | 画面内文字只用一种语言 |
| 参数进正文 | 提示词里写“16:9、24fps” | 比例、时长、分辨率放生成设置 |
| 编造参数版本 | 凭记忆写版本号 | 以官方最新文档为准 |

## 中英文提示词取舍总表

| 任务类型 | 推荐语言 | 原因 |
|---|---|---|
| 生图（Midjourney、Flux、Stable Diffusion） | 英文优先 | 训练数据以英文为主，英文提示词更稳；参数全是英文 |
| 生视频（Seedance、Kling、Veo、Sora、Runway、Luma） | 英文优先 | 运镜、镜头语言用英文更准；锁定句式和音频标记是英文语法 |
| 中文模型生图生视频（即梦、可灵、海螺） | 中文优先 | 中文模型，中文提示词效果最好 |
| 图像编辑（GPT 图像、Nano Banana） | 中英文都行 | 自然语言编辑对中文理解好，按用户说的语言出 |
| 文案 / 营销 | 按受众语言 | 中文受众出中文，英文受众出英文；口号不直译 |
| 代码 / Agent 指令 | 按任务语言 | 需求中文就写中文需求；标识符、注释习惯用英文 |
| 教育 / 办公 | 按受众语言 | 给中国学生、中文职场出中文；海外受众出英文 |
| 画面内文字（招牌、字幕、标签） | 只用一种语言 | 中文画面全中文，英文画面全英文，不混用 |
| 模型参数（`--ar`、`--no`）和锁定句式 | 永远英文 | 平台语法，改写就失效 |

## 中文想法转英文提示词的要点

直译会翻车的地方，逐条对照着改：

1. **抽象词先拆再翻**：“氛围感”不要翻成 `atmosphere feeling`，拆成可见元素再翻——低暖光 + 薄雾 + 安静街道（`low warm light, thin haze, quiet street`）。“高级感”不要翻成 `high-level feeling`，拆成 muted 色调 + 哑光材质 + 大量留白。“治愈”不要翻成 `healing`，用 `soothing / calm / warm`。
2. **成语、网络梗不直译**：“画蛇添足”“绝绝子”“种草”“爆款”没有英文对应词，硬翻模型读不懂。换成画面描述，或删掉。完整对照见 `bilingual-glossary.md` 的翻译避坑速查。
3. **颜色词按英文习惯翻**：“米白”翻 `cream / off-white`，不要翻 `rice white`；“高级灰”翻 `muted gray tones, low saturation`，不要翻 `high-level gray`。
4. **数量写死**：中文说“几个”很含糊，英文必须写确数（`one / two / three`）；“一些”不要写 `some`，直接写数字。
5. **语序倒过来**：中文习惯先说环境再说主体（“清晨的厨房里，一只橘猫……”），英文先说主体再说环境（`an orange tabby cat in a quiet kitchen at dawn...`）。修饰语放名词前面（`warm afternoon light`，不要写 `light of warm afternoon`）。
6. **被动改主动**：中文“被雨淋湿的街道”翻成 `a rain-soaked street`，不要翻 `the street that was wetted by rain`；英文提示词多用主动语态和名词短语。
7. **“很 + 形容词”换成具体描述**：“很漂亮的女孩”不要翻 `a very beautiful girl`，写具体长相——二十岁左右、黑色长发、白色连衣裙、站在窗边回头。“他努力跑”不要翻 `he runs with all his might`，写画面——招牌飞速后退、脚后扬起灰尘。
8. **术语全文统一**：同一个概念只用一种说法。写完后通读一遍，前面叫“首尾帧”、后面叫“first-last frame”就是不一致，统一掉。对照表见 `bilingual-glossary.md`。
