# 优化检查清单（optimization-checklist）

收到一段提示词，先按这张清单逐项打勾，列出问题再动手修。不要边读边改。

---

## 一、快速过一遍（30 秒）

| # | 检查项 | 过关标准 |
|---|---|---|
| 1 | 主体清楚吗 | 一眼能说出画面里是谁 / 什么、有几个 |
| 2 | 风格锁死了吗 | 全篇只有一个风格方向 |
| 3 | 有光吗 | 写了光源、方向、质感，至少占一样 |
| 4 | 有镜头吗 | 写了景别、角度，至少占一样 |
| 5 | 有否定词吗 | `no / without / don't / never` 出现即标红 |
| 6 | 有模糊词吗 | beautiful / amazing / stunning / 高质量这类空词出现即标红 |
| 7 | 画面文字单语言吗 | 招牌、字幕、标签只用一种语言 |
| 8 | 长度合适吗 | 图片提示词建议 150 词以内；视频单 clip 建议 200 词以内 |
| 9 | 中英一致吗 | 没有翻译腔、没有中英混杂、术语前后统一 |

9 项全过，基本能交；有一项不过，进第二部分细查。

---

## 二、逐项细查

### 1. 缺失维度

对照图片九维 / 视频七维，逐个问“写了没”。

- 图片：主体、风格、材质、光线、构图、镜头、色彩、氛围、画质词。核心四维（主体、风格、光线、镜头）缺一不可，其他维度缺了可以补，补不出来就问用户。
- 视频：主体运动、镜头运动、时间节奏、转场、首尾帧、音频、一致性。缺“一致性”最常见——多镜头短片没写一致性，人物一定跑偏。
- 修复手法：按原提示词的意图补，不要另起炉灶；补不出来的问用户一句，不要猜。

### 2. 矛盾描述

两处互相打架的，留一个、删一个，不要两个都留着让模型猜。

常见矛盾：

- 时间打架：又说“夜晚”又说“阳光明媚”。
- 天气打架：又说“下雨”又说“干燥的地面”。
- 镜头打架：又说“固定机位”又说“环绕运镜”。
- 风格打架：开头写实、结尾卡通。
- 数量打架：前面说“一个人”，后面出现“他们”。
- 修复手法：按用户的核心意图留一个，另一个删掉或改写。

### 3. 模糊词

模型无法执行的空词，全部换成可见的具体描述。

| 模糊词 | 换法 |
|---|---|
| beautiful / 美丽 | 写出具体长相：二十岁左右、黑色长发、白色连衣裙 |
| high quality / 高质量 | 写出画面特征：细节清晰、边缘干净、没有噪点 |
| amazing / stunning / 震撼 | 写出画面冲击点：巨大的浪头、满天繁星、低角度仰拍 |
| cozy / 温馨 | 写出可见的布置：暖色台灯、毛毯、半杯热茶 |
| epic / 史诗感 | 写出规模感：千人队列、连绵山脉、广角全景 |
| cute / 可爱 | 写出具体样子：圆滚滚的身体、大眼睛、短短的腿 |

### 4. 否定词与废话

- `no / without / don't / never`：每出现一次，改写成正面状态，或删掉导致它的那句话。真正不要的画面通病，放进负向提示词（见 `prompt-anatomy.md` 负向词表）。
- 画质词堆叠：`8k, ultra detailed, HDR, best quality, masterpiece` 留一两个，其余删掉。
- 重复：同一意思写两遍的，删一遍；同一形容词出现三次以上的，留一次。
- 空话：`in the image / in this picture / as you can see` 这类对画面没帮助的词，直接删。

### 5. 结构问题

- 太长：按重要性排序，次要的移到负向提示词或删掉；不要为了凑字数加形容词。
- 太散：没有分段、没有主次的，重排成“主体 → 环境 → 光线 → 镜头 → 氛围”的顺序。
- 风格漂移：全篇锁定一种风格词，其他风格词删掉。
- 语言混用：提示词正文统一英文；画面内文字（招牌、字幕、标签）单独处理，只用一种语言。
- 首尾帧：视频有首尾帧锁定的，确认两帧比例一致、锁定句式一字不差。

### 6. 对白与声音

- 对白是不是用户原话：不是就删掉，改成嘴部动作、停顿、姿势。
- 声音有没有落到具体的东西上：`background music` 太空，改成 `(soft piano, slow)`；`sound effects` 太空，改成 `<rain on metal>`。
- 音乐、音效、对白、字幕的标记有没有分开写。

### 7. 参考图与角色

- 多张参考图有没有编号、分工：一张图一个角色、一行写清，没写的补上。
- 角色锚点注册后有没有重复描述长相：有就删掉重复的部分，只留动作、服装状态、光线。
- 环境参考有没有被当成固定机位：只需要风格时，写明“只是风格参考，不是固定机位，模型可以自己扩展世界”。

### 8. 中英专项检查

- **翻译腔**：抽象词直译（`atmosphere feeling`、`high-level feeling`、`healing`）出现即标红，换成可见的画面描述；“米白”翻成 `rice white`、“种草”翻成 `plant grass` 这类硬译一并改掉。对照见 `bilingual-glossary.md` 的翻译避坑速查。
- **中英混杂**：提示词正文里中英混排（英文句子中间夹中文词、中文句子中间夹英文词）即标红，按目标语言统一。例外：模型参数（`--ar`、`--no`）和锁定句式（`@Image N is the first frame.`）本来就是英文，不算混杂。
- **术语不一致**：同一概念前后两种说法（前面“首尾帧”、后面“first-last frame”；前面“运镜”、后面“camera move”混着用），全文统一成一种。
- **中文残留**：英文提示词里夹着没翻的中文词（“一只橘猫”混在一堆英文里），翻成英文或删掉。
- **文化意象直译**：成语、网络梗、双关硬翻成英文（“绝绝子”翻成 `absolutely amazing`），模型读不懂，换成画面描述或删掉。
- **语序问题**：中文语序直搬到英文（先环境后主体、修饰语放名词后面），按英文习惯调整：主体在前，修饰语在名词前。

## 三、优化前后对照表（交付时用）

```markdown
**诊断**
- 问题 1：……（缺失 / 矛盾 / 模糊 / 否定 / 结构）
- 问题 2：……

**改了什么**
- ……（每条改动写清原因）
```

没有问题的部分不要动。优化不是重写，原提示词里好的句子原样保留。

---

## 四、常见“修完反而更差”的情况

- 补了太多细节：原提示词本来很干净，补了一堆用不上的维度，反而把主体挤没了。只补缺失的核心维度。
- 把用户的口语全改成术语：用户说“暖暖的黄昏”，不用非改成“golden hour backlit”。意思到了就行。
- 为了押韵 / 对仗改句子：提示词不是作文，顺口不重要，意思清楚才重要。
- 把短提示词拉长一倍：短提示词如果 8 项全过，就不用动；长不等于好。
